# 手順の集約対応

Windows・AlmaLinux の実施手順の正本は2冊のセットアップ。AI コーディングエージェントの実施手順は、2026-10-14 に 3 冊目の [docs/ai-agents.md](../ai-agents.md) へ分けた（[追補](#ai-エージェントの手順を-ai-agentsmd-へ分けたときの追補)）。案内だけになった個別手順37文書と bash の導入案内は削除した。固有の仕様・他 OS の操作・開発用検査・検証・参考資料・ロールバックは元の場所に保持する。検証記録は非公開の `ryo-aoki-pc/setup-notes-verification` の同じパスにある。

- 移動元は集約前の基準コミットに固定し、元のパスと旧見出しを併記する
- 過去の検証の手順番号は当時のもの。次の対応表で現在の節を確認する
- 既存の設定内の識別印・バックアップ名・ツールの実装は変更しない
- 集約時の静的検査・回帰検査と削除後の確認は [検証記録](https://github.com/ryo-aoki-pc/setup-notes-verification/blob/main/docs/verification/consolidation.md) に記録する

集約後に main へ入った [Codeg の Windows 公開範囲の更新（0e8dc65）](https://github.com/ryo-aoki-pc/setup-notes/commit/0e8dc6589485cd4205ff5d0d0618511a156da0b4)も正本と関連資料へ反映した。下表の移動元は当初の基準を保つ。

[VirtualBox の使用手順と Hyper-V の検証記録の追加（421be2d）](https://github.com/ryo-aoki-pc/setup-notes/commit/421be2df74f6120da0168d8e9b5cbeac9af8dda1)も反映した。当初の対応322件を保持し、後から加わった見出し8件は末尾の追補に記録する。

## 2 冊をカテゴリ別に組み直したときの追補

2026-10-14 に、利用者の依頼で、[docs/windows-setup.md](../windows-setup.md)・[docs/almalinux-setup.md](../almalinux-setup.md) の「実施手順」と任意節（必須・任意）の区別をやめ、カテゴリ別の `##` の大見出しの下に組み直した。どの項も単独で通せるように、項ごとに前提・実行場所を書き、変数と窓を開く手順を項の中に持たせた。移動元の基準は setup-notes の `21e8fa1517a504267031f6dc83d2a72f66ee3bce`。骨格は [writing-rules.md の「2 冊の骨格（カテゴリ別）」](writing-rules.md#2-冊の骨格カテゴリ別)。

- 見出しは `##` カテゴリ → `###` 用途 → `####` 手順。見出しの名前は保ち、「（任意）」「（導入前・任意）」を外した
- `<用途>: 実施手順` と Windows の `<用途>: Windows 11 で使う` は畳み、本文を `### <用途>` へ移した。旧アンカーは `### <用途>` を指す
- 「設定リポジトリと追加の道具（任意）」の見出しは外した（子の項は、それぞれのカテゴリへ移した）
- AlmaLinux 10 の「更新」は、リードを `## 更新` に、手順を「共通の bash 設定・Homebrew・Flatpak を上げる」に分けた
- 参考資料の補足の見出しは、`<節> / <項> / 手順 N` を `<項> / 手順 N` にし、手順番号を下の表に合わせた。両 OS の参考資料の Windows 側の主の補足は「Windows 11 の <用途> / 手順 N」にした
- 過去の検証記録の手順番号は書き直していない。旧の番号は、下の「手順番号の対応」で今の番号に読み替える
