### 用途ごとの注意

- `README.md` — 手順書（正本）の表と、用途から探す短い案内、置き場所と記法。手順書を足したら「手順書」の表に 1 行と、合う「用途から探す」の節に 1 行のリンクを足す（合う節が無ければ節を足す）。用途の節は 1〜2 行の箇条書きにし、表・版・検証範囲・入る場所などの細目は書かず、手順書・導入元一覧・検証記録に任せる。`共通の bash 設定を先に入れる`・`導入の基盤`・`記法` の見出しは、ほかの文書と非公開の検証記録からリンクされているので文字を変えない。手順書の無いツールは導入元一覧（`docs/tool-catalog.md`）だけに載せる。知見は `docs/reference/<手順書名>.md`、実測は `docs/verification/<手順書名>.md`、注意点は `docs/extra/<手順書名>.md` に置く
- 共通の bash 設定は `docs/shell-terminal.md` の「共通の bash 設定」と「Git Bash と WezTerm の設定」で導入する。各ツールの手順には `~/.bashrc` へ直接追記・削除するブロックを置かず、共通設定の読み込みと確認だけを書く。starship を入れた後は `. ~/.bashrc` で読み直さず、WezTerm の新しいタブで確かめる（WezTerm のシェル統合より後ろになるため）。共通設定の行を変える・足すときは、bash リポジトリの `bashrc`・README の「読むもの」と `docs/reference/readme.md` の表も合わせる。root のシェルで読む設定は、一般ユーザーを信用できるホストだけに入れ、`DOCKER_HOST` は `/run/podman/podman.sock` を使う
- `docs/gnome-remote.md` — 「GNOME のリモートログイン」: 変数ブロックを冒頭に置き、以降のコマンドをそのまま貼れる形式。手順 5 で `gnome-remote-desktop.service` に `After=gdm.service` のドロップイン（`/etc/systemd/system/gnome-remote-desktop.service.d/10-after-gdm.conf`）を置く（無いと起動のときに GDM より先に立ち上がり、GDM がバス名を取ってから表示の一覧を公開するまでのすき間で GetManagedObjects が失敗する。GLib 2.80 の GDBusObjectManagerClient はそのとき子のシグナルの購読を外したままにするので、ログイン画面の表示の `SessionId`〔PropertiesChanged〕が届かず、その起動の間はリモートログインがいつも真っ暗な画面のまま 30 秒で切れた）。「GNOME のリモートログイン: デーモンを起動し直す」では、`restart` ではなく stop → 5 秒 → start を使う（`restart` では、閉じるログイン画面の表示を新しいデーモンが取りこぼし、GDM が同じパスを使い回した次の接続が真っ暗になった。ヘッドレスのセッションがある PC では、続けてそのユーザーの `gnome-remote-desktop-handover.service` を再起動する〔RHEL のパッチの受け渡し役は、引き渡し口を取り直し損ねて黙って止まる〕）。
  - 手順 11 は、AlmaLinux 10 の `freerdp` パッケージに `xfreerdp3` が無いので、`xfreerdp` を使う。手順 11 に FreeRDP の入力待ち（証明書の `(Y/T/N)`・`Domain:`・`Password:`）と、初めての接続でも出る `REMOTE HOST IDENTIFICATION HAS CHANGED!` の警告・Kerberos の `[ERROR]` の行、手順 3 に確認の箇条書き、手順 4 に TPM の無い PC で出る `Init TPM credentials failed …` の行と「TLS fingerprint は手順 10・11 で使う」を置く。手順 9・10 の `openssl`・`python3` は PATH 任せのまま。
- `docs/samba.md` — `[homes]` 共有でホームディレクトリを公開する手順書。環境固有の値は用途ごとの変数ブロックで設定する。サーバーの上の動作確認（資格情報ファイル・`smbclient`・`mount.cifs`・後片付けと、root の節の `/root` の確認）は「サーバーの上で動作を確かめる」に置く（骨格の例外。導入は手順 9 のクライアントからの接続で終わり、root の節の手順 3 は再起動だけ）。手順 3 の smb.conf の字下げは空白にする（TAB は bash の補完で `.` に置き換わる）。任意節「root のホームも公開する」は、smb.conf の末尾に `[root]` 共有（`path = /root`・`valid users = <USER>`・`force user = root`・`browseable = No`）を足し、root の Samba ユーザーは作らない（Windows のエラー 1219 を避け、root にパスワードで入る口を作らない）。`/root` の `admin_home_t` は `samba_enable_home_dirs` の対象（`user_home_type`）に入っていないので、boolean が `user_home_type` に許すのと同じ許可を `admin_home_t` に足す CIL のモジュール `samba_root_home` を `semodule -i` で入れる（`/root/.ssh` などの `user_home_type` のラベルは boolean で既に許されているので、`.ssh/authorized_keys` も読み書きできる。WARNING に root と同じ重みと書いた）。任意節「/home も公開する」は、smb.conf の末尾に `[home]` 共有（`path = /home`・`valid users = <USER>`・`force user = root`・`inherit owner = yes`・`browseable = No`）を足す（ほかのユーザーのホームは 0700 なので root として開き、作ったものは `inherit owner` で親ディレクトリの所有者にする〔グループは root〕。無いと、一時ファイルに書いて改名で保存するアプリで、持ち主のファイルが `root root` に変わる）。SELinux は手順 4 の boolean だけで足り（`smbd_t` は `home_root_t` を読める）、`/home` の直下への作成は SELinux が断るままにする（samba-client.md の `SHARE=home` の手順 5・7 の書き込みも `Permission denied`）。確かめは動作を確かめる節の手順 9・10。手順 3 の `[global]` に `smb3 directory leases = no` を入れる（Samba 4.22 からの既定ではクライアントにディレクトリのリースを渡し、Samba を通さずにサーバーで変えたもの〔シェルや同期の道具〕ではリースを破らないので、Windows のエクスプローラーは F5 でもウィンドウを開き直しても古い一覧を出し続けた）。
- `docs/samba.md` — 「Samba クライアント・Windows 11 で Samba クライアントを使う」: samba.md の共有を AlmaLinux 10 の PC から使う手順書。Windows 11 の操作も扱う。samba.md と同じ変数ブロック方式（必須は `SERVER` だけ。`SMB_USER` / `SHARE` / `MOUNT_POINT` の既定は `${USER}` / `${SMB_USER}` / `/mnt/${SHARE}`。samba.md の `[root]` には `SHARE=root`、`[home]` には `SHARE=home` だけを変えてつなぐ。`SHARE=home` では手順 5 の書き込みが `Permission denied` になる）。`cifs-utils` を入れ、資格情報を `/root/smb-<SMB_USER>@<SERVER>.cred`（root の 0600）に置き、手で 1 度マウントして確かめてから、`/etc/fstab` に `x-systemd.automount,x-systemd.idle-timeout=1min` の行を足す（`_netdev` と `nofail` は付けない。理由は同書の「選択した方針」）。`sudo` の後ろに行が続くブロックは、どれも 1 つのコマンド（`if … fi` や `{ … }`）にしてある（ブラケットペースト無しで貼ると、sudo 1.9.17 の `use_pty` が残りの行を吸い、手順 5 の `umount` が実行されなかった）。変数が空のときの中断は、ブロックの先頭の `if [ -z … ]` で行う（パイプや `$(…)` の中の `${VAR:?}` はブロックを止めず、直す前の手順 4 は空の `/root/smb-@<SERVER>.cred` を作った）。GNOME Files（`gio mount`、gvfs-smb）は任意節。注意点に、ディレクトリのリースを渡すサーバー（Samba 4.22 以降の既定）では cifs が一覧を 30〜60 秒キャッシュし、サーバーで直接変えたものが `ls` に出ないこと（`nohandlecache` で避けられる）と、GNOME Files は自動では出ず F5 で出ることを置く。
  - Windows 11 の節: **管理者ではない** Windows PowerShell 5.1 に貼る（管理者の窓で割り当てたドライブはエクスプローラーに出ない）。必須の変数は `SERVER` と `SMB_USER`（Windows のユーザー名と違うことが多いので既定値を置かない）、任意は `SHARE`・`DRIVE`（既定 `Z:`）。445/tcp と、ドライブ文字が空いていること（切れたまま覚えている割り当ても `Get-SmbMapping` で見る）を確かめ、`cmdkey "/add:$SERVER" "/user:$SMB_USER" /pass`（対話入力）で資格情報マネージャーに置いてから、資格情報を渡さずに `New-SmbMapping -Persistent $true` で割り当てる。読み書き、サーバーに貼る `bash` のブロックの `sudo smbstatus`（`SMB3_11` と署名）、サインアウトとサインインで確かめる。24H2 の Pro・Enterprise・Education は SMB の署名を必須にしゲストを断るが、samba.md の smb.conf（`server signing`・`map to guest` は既定）のままで合うので、サーバーもクライアントも変えない（Home は署名を求めない）。注意点に、Home・エラー 1219・サインインのときの赤い ×・管理者の窓では UNC・`BlockNTLM` を足した。samba.md 手順 9 の Windows の箇条書きから案内する。
- `docs/windows-setup.md` — 「RDP をロックせずに切断」: Windows 11 の PC に RDP でつないで使った後、PC の画面をロックさせずに切断する（ふつうに切断すると、セッションは `Disc` で残り、PC の画面はロック画面になる）。手順 1〜3 は RDP でつないだセッションの中の管理者の Windows PowerShell 5.1 で、`quser` で `rdp-tcp#<N>` を確かめてから `tscon.exe (Get-Process -Id $PID).SessionId /dest:console` を貼る（その場で RDP が切れる。ID は `quser` の列を切り出さずにプロセスから取る）。手順 4 は、PC の画面でロック画面にならず元のデスクトップが表示されることを確かめる。変数は無い。任意節「ショートカットで切断する」は、`WScript.Shell` でデスクトップに `RDP をロックせずに切断.lnk`（`powershell.exe -NoProfile -WindowStyle Hidden -Command "tscon.exe … /dest:console"`）を作り、`.lnk` のオフセット `0x15` に `0x20`（MS-SHLLINK の `LinkFlags` の `RunAsUser`）を立てて「管理者として実行」にする（毎回 UAC。UAC を出さないタスク経由の形は、仕組みが増えるので採らなかった）。
- `docs/windows-setup.md` — Windows 11 をインストールした直後に行う基本の設定・デスクトップ・ネットワークとリモート操作・SSH・Git と開発の道具・アプリの手順を扱う
